# Code Intelligence

This workspace is indexed by **code-intelligence**, a persistent,
incremental, symbol-oriented index. Query it instead of opening whole
files — most questions ("where is X defined", "what does this function's body look like", "what breaks quality rules here") are answered by a small,
precise query, not a full-file read.

## Prerequisite

The tool itself lives outside this workspace, at `/home/ensismoebius/dotfiles/code_intelligence`. Invoke it as:

```bash
CQ_PY="/home/ensismoebius/dotfiles/code_intelligence/.venv/bin/python"
CQ_SCRIPT="/home/ensismoebius/dotfiles/code_intelligence/code-intelligence.py"
test -x "$CQ_PY" || echo "code-intelligence not found at /home/ensismoebius/dotfiles/code_intelligence on this machine — skip these checks, don't reimplement or vendor a copy without asking first"
```

Every command below is `$CQ_PY $CQ_SCRIPT <subcommand> ...`, run from this
workspace's root.

## Query-before-you-read workflow

1. **Structure first, content last.** Start at the cheapest level that
   answers your question:
   - `$CQ_PY $CQ_SCRIPT query <path>` — per-file summary across the whole
     workspace (files, languages, symbol/violation counts).
   - `$CQ_PY $CQ_SCRIPT query <path> --file <relpath>` — every symbol in
     one file (kind, name, location, LOC, complexity) — no source text.
   - `$CQ_PY $CQ_SCRIPT symbol <symbol_id-or-name> [--file <relpath>]` —
     one symbol's full metadata (calls, called-by, violations) — still no
     source text.
   - `$CQ_PY $CQ_SCRIPT context <symbol_id> [--max-lines N]` — the
     symbol's actual source, budgeted. If it would exceed the budget you
     get `{"truncated": true, "available_range": ..., "recommended_ranges": [...]}`
     instead of a silently clipped body — never guess at a smaller range
     yourself, read what it recommends.
   - `$CQ_PY $CQ_SCRIPT range <path>:<start>-<end>` — an exact line range
     when you already know precisely what you need.
2. **Check violations before editing.** `$CQ_PY $CQ_SCRIPT violations
   [--severity SEV]` lists structural findings (naming, missing docs,
   multiple types per file, procedural monoliths, duplication, LOC/
   function-length thresholds) with `symbol_id`/location — narrower and
   cheaper than reading a file to spot problems yourself.
3. **Re-index after you change code.** `$CQ_PY $CQ_SCRIPT index` is
   incremental (only changed files reparse); run it again before your next
   query so results reflect your edits.
4. **Comparing against a point in history?** `$CQ_PY $CQ_SCRIPT diff
   <ref>` (`HEAD`, `HEAD~1`, `working-tree`, `staged`, a branch, a commit)
   reports `added_symbols`/`removed_symbols`/`changed_symbols`/
   `changed_files`/`new_violations`/`resolved_violations`/`regressions`
   without a full re-scan.

## Notes

- `.code-intelligence/` (the SQLite index + this bootstrap marker) is
  workspace-local state, not meant to be committed — it's added to
  `.gitignore` automatically.
- Every finding and every symbol can carry a `confidence` field
  (`"high"`/`"medium"`/`"low"`) — a heuristic (e.g. cross-file duplication
  similarity) is never presented as certainty.
