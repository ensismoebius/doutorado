## BUG: Thesis experiment profiles missing from git (must be tracked)

**Scope:** `software/nn/` — `src/experiments/thesis/profiles/`

**Impact:** `ctest` fails **201 tests** on every checkout — all
`ThesisProfileAuditTest::*` cases in
`software/nn/src/experiments/thesis/tests/thesis_profile_audit_gtest.cpp`.

### Root cause (confirmed)

1. The audit test hardcodes an expected set of 241 profile paths (all under
   `phase00/` and `phase01/`). 216 of them exist and are tracked.
2. **25 are missing entirely** — neither on disk nor in git:
   - `debug.json`
   - 24× `phase00/p00_ae_*` (autoencoder family): `p00_ae_ann_*` (6),
     `p00_ae_snn_direct_*` (6), `p00_ae_snn_latency_*` (6),
     `p00_ae_snn_poisson_*` (6) — `{base,small,tiny} x {eeg,voice}` each.
3. Root cause of non-tracking: the repo-root `.gitignore` line 37 is a
   blanket `*.json` (added in commit `34498a79`, "Using core dataloader").
   It swallows every `.json` under `software/nn/`, so the thesis profile
   JSONs can never be `git add`-ed. The `p00_ae_*` set was never committed
   (and is currently absent from disk too, so it isn't just an ignore
   problem — the files need to be regenerated/restored as well).

### Fix plan

1. Scope the ignore rule: in repo-root `.gitignore`, un-ignore the thesis
   profiles, e.g.
   ```
   !software/nn/src/experiments/thesis/profiles/
   !software/nn/src/experiments/thesis/profiles/**/*.json
   ```
   (Keep `*.json` for the rest of the tree. Verify with
   `git check-ignore -v` on a profile.)
2. Restore/generate the 25 missing profiles:
   - `debug.json` — regenerated by
     `software/nn/scripts/testing/thesis_make_smoke_profiles.py`.
   - `p00_ae_*` (24 files) — the autoencoder phase-00 profiles; recreate
     them (see the `p00_hc_*` siblings for the schema, and
     `software/nn/scripts/testing/run_thesis_profiles.sh` for how they are
     consumed).
3. `git add` them and verify:
   - `git status --short` shows the 25 files as tracked additions.
   - `ctest --test-dir out/build/debug-macos -R ThesisProfileAudit` passes.
4. Guard against recurrence: consider a CI check that every filename in the
   audit test's hardcoded list exists on disk (or generate the list from
   the directory at test-build time so the test and the repo can't drift).
