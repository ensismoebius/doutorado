# How to Change Anything

## Why this page exists

A change in this project is rarely one file. Adding a profile key, for example, touches the
schema, the code that reads it, the script that generates profiles, a test, and this wiki;
forgetting one of them usually fails **silently**. A key the generator never writes is caught
by the strict config. A doc that still describes the old key is caught by nothing. So every row
below answers four questions:

```
   what to edit  ──►  how to check it  ──►  what else must follow  ──►  which doc to update
   (code)             (test / command)      (profiles, results, text)   (wiki / README)
```

Paths are relative to `software/nn/` unless they start with `documentation/`. Before changing
behaviour that a stored result depends on, read the [Engineering Fixes Log](./Engineering-Fixes-Log.md):
several "obvious" simplifications were bugs that invalidated runs.

## The framework (`include/`, `src/core/`)

| I want to… | Edit | Check with | Then |
|---|---|---|---|
| add a layer | `include/layers/<category>/Foo.hpp` defining `FooImpl<Backend>` (the alias `nn::Foo` is generated by `cmake/GenerateLayers.cmake` on configure) | a numerical gradient check in `src/core/layers/tests/` | [Adding a Layer](../Tutorials/Adding-a-Layer.md); `Core/Layers.md`, `References.md` |
| add a loss | `include/layers/losses/` (`MSELoss.hpp` is the model) | gradient check vs PyTorch: `scripts/testing/gen_pytorch_refs.py` + `pytorch_parity_gtest` | `Core/Layers.md` |
| add or change an optimizer | `include/optimizers/`, register it in `OptimizerFactory.hpp` | `optimizers_gtest`; parity: `gen_optimizer_refs.py` + `optimizer_parity_gtest` | `Core/Optimizers.md` |
| change the training loop | `include/training/` (`Trainer`) | `trainer_gtest`, `trainer_genericity_gtest` | `Core/Training.md` |
| add a tensor operation | `include/tensor/` **and every backend** (XTensor, Device): the parity contract refuses one-backend operations | `tensor_gtest`, `tensor_all_backends_gtest`, `tensor_backend_switchability_gtest` | `Core/Tensor.md` |
| add a backend | `include/Backend.hpp` (the only file allowed to name one; `cmake/BackendImplementationGuard.cmake` enforces it), modelled on `DeviceTensorBackend` | `device_backend_gtest` | `Core/Device.md` |
| add a model (autoencoder, …) | `include/models/<family>/`, `src/core/models/<family>/` | `src/core/models/*/tests/` | `Core/Models.md` |
| add a dataset loader | `include/data_loaders/<doi>/` + `src/core/data_loaders/<doi>/` | its own `tests/` | `src/core/data_loaders/README.md` › Adding a new dataset; `Core/DataLoaders.md` |
| add a data transform / augmentation | `include/utility/` (`ITransform`, `Compose`, …) | `util_gtest` | `Core/DataLoaders.md` › Transforms |
| change wavelets / audio features | `include/wavelet/`, `include/wave/` | `wavelet_gtest`, `pywt_parity_gtest` (`gen_pywt_refs.py`), `wave_gtest` | `Core/Wavelet.md`, `Core/Wave.md` |
| change metrics, EER, k-fold | `include/statistics/` | `statistics_gtest`, `eer_scorer_gtest`, `kfold_gtest` | `Core/Statistics.md` |
| change the paraconsistent score | `include/paraconsistent/` (and `ThesisParaconsistent.*` for `d_penalized`) | `paraconsistent_gtest`; the thesis suites | `Core/Paraconsistent.md` — **this changes every Phase 00 result** |
| change save/load formats | `include/serialization/`, `include/io/` | `core_gtest` (serialization round-trips) | `Core/Saver.md`; keep old files loadable or say why not |
| add a dependency | `cmake/Vendor<Name>.cmake` (fetched) or `cmake/{Ubuntu,ArchLinux,MacOSX}Dependencies.cmake` (system) | a clean configure: `rm -rf out/build/max-performance && cmake --preset=max-performance` | `Guides/Build-System.md` |

## Infrastructure

| I want to… | Edit | Check with | Then |
|---|---|---|---|
| change CI | `.github/workflows/ci.yml` (repository root; runs in `software/nn`) | the run on GitHub (`gh run list`) | [Static Analysis](./Static-Analysis.md) |
| add a Python test to CI | a step in `ci.yml` (stdlib suites: `python3 file.py`; pytest suites: `python3 -m pytest`) | locally first; CI uses Ubuntu's apt Python packages, so pin nothing newer | `scripts/README.md` › testing |
| silence a cppcheck/clang-tidy finding | fix it; a proven false positive gets a one-line `NOLINT(<check>)` / `cppcheck-suppress <id>` with its reason | `run-clang-tidy -p out/build/max-performance 'software/nn/src/'` and `--target analysis-cppcheck` (both must report 0) | [Static Analysis](./Static-Analysis.md) |
| run on the cluster | `scripts/pipeline/meeting01/gridunesp_deploy.sh`, the `.sbatch` of the experiment | `run_gridunesp_docker_sim.sh` rehearses the toolchain locally | [GridUnesp Deployment](./GridUnesp-Deployment.md) |
| add a wiki page | `.wiki/<Section>/Page.md`, linked from `Home.md` | no broken links, no orphan page | follow `/didactic-explanation` (problem first, one real example, the failure mode) — [Time Steps](../Concepts/Time-Steps.md) is the model |
| add a script | the right `scripts/` folder, every argument required | a test in `scripts/testing/` if a pipeline reads its output | a row in `scripts/README.md` |
